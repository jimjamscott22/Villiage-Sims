# Save Manager — Design

Date: 2026-10-01
Status: approved in conversation, pending written-spec review

## Goal

Replace the fixed "Slot 1" SAVE/LOAD buttons with a save manager overlay:

1. Clicking SAVE (or LOAD) opens an in-game overlay with its own buttons and a list of
   save history.
2. Saves are unlimited and named. The player can save under a new name, or simply save over
   the session they last loaded/saved.

### Problems with the current system (fixed by this design)

- SAVE/LOAD are hardwired to slot 1 (`src/App.tsx` `onSave`/`onLoad`); no names, no
  timestamps, no list.
- The daily autosave rotates through the *same* `slot-{1,2,3}.vsav` files
  (`World` autosave, `sim/weather.rs::autosave_slot_for`), so a manual Slot 1 save is
  silently overwritten whenever the rotation lands on slot 1.
- Load confirmation uses `window.confirm`, which breaks the pixel UI and blocks automation.

## Decisions

| Question | Decision |
|---|---|
| Save model | Unlimited named saves, plus separate rotating autosaves |
| Primary "Save" target | Overwrites the "current session" (last loaded or saved manual save). Fresh worlds and loaded autosaves have no current session |
| Load UI | One overlay for both; SAVE and LOAD toolbar buttons both open it |
| Metadata storage | Per-save JSON sidecar next to each `.vsav` (no save-format change) |

## Storage layout

Directory: `app_data/saves/` (unchanged).

- Manual save: `<id>.vsav` + `<id>.meta.json`
- Autosave: `autosave-<n>.vsav` + `autosave-<n>.meta.json`, `n ∈ 1..=3`, same daily
  rotation as today (`autosave_slot_for`).
- Legacy files (`slot-1..3.vsav`) and any other `.vsav` without a sidecar are still listed
  (see Listing).

`.vsav` contents, header, and `SAVE_VERSION` are **unchanged**; legacy decode paths are
untouched.

### Ids

- Generated by the backend, never derived from the user's name: `s-<unix_ms>`, with a
  `-<n>` suffix if that file already exists. Autosave ids are `autosave-<n>`.
- The save's kind is derived from its id prefix, not trusted from the sidecar.
- Every id received from the frontend is validated against `^[a-z0-9-]{1,64}$` before any
  path is built. Invalid → `Err("invalid save id ...")`. This blocks path traversal.
- Rename edits the sidecar only; the file name never changes.

### Sidecar schema (`<id>.meta.json`)

```json
{
  "name": "Riverbend",
  "kind": "manual",            // "manual" | "autosave"
  "savedAt": 1790000000000,    // unix ms, wall clock at write time
  "year": 2, "season": 1, "day": 4,
  "population": 14
}
```

Written atomically with the same temp-file-then-rename approach as `persist::save_world`.
The `.vsav` is written first, then the sidecar; a crash between them leaves a `.vsav`
without (or with stale) metadata, which the listing tolerates.

## Backend API (Tauri commands)

Slot-based `save_game(slot)` / `load_game(slot)` are removed.

```ts
interface SaveInfo {
  id: string;
  name: string;
  kind: 'manual' | 'autosave';
  savedAt: number;          // unix ms
  year: number | null;      // null when metadata is missing
  season: number | null;
  day: number | null;
  population: number | null;
}
```

| Command | Behavior |
|---|---|
| `list_saves() -> SaveInfo[]` | Scans `saves/` for `*.vsav`. Newest `savedAt` first. Missing/unreadable sidecar → name = file stem, kind = `autosave` if stem starts with `autosave-`, else `manual`; `savedAt` = file mtime; game fields null. Never decodes `.vsav` payloads. Missing directory → empty list |
| `save_game(id: string \| null, name: string) -> SaveInfo` | `id` null → create a new id. `id` given → overwrite that save (must exist and be `manual`). Name validated (below). Writes `.vsav` via the sim command channel, then the sidecar |
| `load_game(id) -> WorldInit` | Same as today's load, by id |
| `rename_save(id, name) -> SaveInfo` | Manual saves only; rewrites sidecar |
| `delete_save(id) -> ()` | Removes `.vsav` and sidecar (sidecar missing is fine). Autosaves deletable |

Name validation (backend is authoritative, frontend mirrors it): trimmed, 1–40 chars,
no control characters. Duplicate names allowed.

Population and in-game date for the sidecar come from the `World` at save time — the
`SaveGame` sim command reply is extended to return them (or a small `SaveSummary`) so the
command layer can write the sidecar without a second round-trip.

### Autosave

`World`'s day-rollover autosave writes `autosave-<n>.vsav` plus a sidecar named
`Autosave <n>`. `last_autosave_slot` and the snapshot's `lastAutosaveSlot` stay as-is
(status text only).

### Module placement

New `src-tauri/src/saves.rs` owns: id generation/validation, name validation, sidecar
read/write, listing, rename, delete, and path building. `commands.rs` keeps thin Tauri
wrappers. `persist.rs` stays focused on the `.vsav` byte format. The autosave path in
`world.rs` calls into `saves.rs` for its file names and sidecar.

## Frontend

### Transport

`Transport` gains `listSaves`, `saveGame(id | null, name)`, `loadGame(id)`,
`renameSave(id, name)`, `deleteSave(id)`; the slot methods are removed.

`BrowserTransport` implements the same contract on its in-memory map (keyed by id, storing
`{ info: SaveInfo, state: string }`), including autosave entries written by
`DemoWorld.bindAutosave` under `autosave-<n>` ids. Same validation and error strings as Rust
where practical.

### Pure logic — `src/state/saves.ts` (Vitest, Node env)

- `validateSaveName(raw) -> { ok: true, name } | { ok: false, error }`
- `sortSaves(list)` and `groupSaves(list) -> { manual, autosave }`
- `formatGameDate(info)` → `"Y2 Summer D4"` or `"—"` when null
- `formatSavedAt(savedAt, now)` → `"just now"`, `"2m ago"`, `"1h ago"`, else short date
- `nextCurrentSave(current, event)` — current session bookkeeping:
  - saved manual `id` → `{ id, name }`
  - loaded manual → `{ id, name }`; loaded autosave → `null`
  - renamed current → updated name; deleted current → `null`

### Overlay — `src/ui/SaveDialog.tsx`

Built from existing `pixel-panel` / `pixel-btn` / `PixelText` styles, modal over the game.

```
┌─ SAVES ───────────────────────────────── [X] ┐
│ Current: Riverbend                           │
│ [ SAVE ]  overwrites "Riverbend"             │
│ Save as new: [ name...............] [SAVE AS]│
│──────────────────────────────────────────────│
│ MY SAVES                                     │
│ ▸ Riverbend    Y2 Summer D4 · pop 14 · 2m ago│
│                     [LOAD] [RENAME] [DELETE] │
│ ▸ First try    Y1 Spring D9 · pop 6 · Sep 28 │
│ AUTOSAVES                                    │
│ ▸ Autosave 2   Y2 Summer D3 · pop 14 · 1h ago│
│                              [LOAD] [DELETE] │
└──────────────────────────────────────────────┘
```

Behavior:

- Opens from SAVE (name field focused) or LOAD (list focused). Fetches `listSaves()` on open.
- No current session → "Current: Unsaved village", primary SAVE disabled; save via SAVE AS.
- Primary SAVE with a current session asks inline: "Overwrite 'Riverbend'? [YES] [NO]".
- Load / delete confirm inline by swapping the row into a confirm state
  ("Load 'X'? Unsaved progress will be lost. [YES] [NO]"). `window.confirm` is removed.
- Rename turns the name into an input; Enter commits, Esc cancels.
- Empty list → "No saves yet."
- While open the sim is paused; on close the previous speed is restored. Esc / [X] closes,
  disabled while an operation is in flight.
- Errors render inline at the bottom of the dialog.
- After a successful save or load the dialog closes, the toolbar status updates
  (`Saved · Riverbend`, `Loaded · Riverbend`), and a short floating-text confirmation appears
  (the toast stack is chronicle-driven, so the existing floater is used instead).
- Game hotkeys (Canvas and App) are ignored while typing in an input or while a modal is
  open, so typing a save name can't rotate, toggle fullscreen, or demolish.

### App.tsx changes

- Remove `onSave`/`onLoad` slot code; both buttons open the dialog.
- Hold `currentSave: { id, name } | null` in state, updated via `nextCurrentSave`.
- Extract the post-load reset block into `resetAfterWorldSwap()`.

## Error handling

- All backend errors are returned as `Err(String)` and shown inline in the dialog.
- Corrupt/missing sidecars never fail `list_saves`; they fall back as described.
- Failure to write the sidecar after a successful `.vsav` write returns an error, but the
  save itself remains loadable and listed (fallback name).
- Overwriting or renaming an id that doesn't exist → `Err("save not found")`.
- Renaming an autosave → `Err("autosaves cannot be renamed")`.

## Testing

Rust (`cargo test --lib`):
- id validation rejects `../x`, uppercase, empty, >64 chars, slashes.
- name validation (trim, length, control chars).
- create → list → rename → overwrite → delete round-trip in a temp directory.
- listing tolerates `.vsav` without sidecar and corrupt sidecar JSON; legacy `slot-1.vsav`
  appears as `manual` named `slot-1`.
- autosave writes `autosave-<n>.vsav` + sidecar and never touches manual files.
- existing persist round-trip/migration tests remain green.

Vitest:
- `saves.ts` pure functions.
- `BrowserTransport` save CRUD, overwrite, autosave entries appear with kind `autosave`.

Manual / browser smoke (`npm run dev`): open dialog, save-as, overwrite, rename, load,
delete, Esc closes and restores speed.

## Out of scope

- Save thumbnails/screenshots.
- Import/export of save files.
- A "New world" button.
- Migrating/renaming existing `slot-*.vsav` files on disk (they are simply listed).
